Introduction au Free Surf

Avertissement et Éthique : Le but de ce guide est strictement éducatif. Les informations et techniques partagées visent à démystifier le fonctionnement des réseaux et à illustrer des concepts de sécurité informatique. Leur mise en pratique peut enfreindre les CGU de votre FAI. Agissez en apprenant responsable.
Le "Free Surf" consiste à utiliser des techniques spécifiques pour accéder à Internet via un réseau mobile sans consommer son forfait de données principal. Cela repose sur l'exploitation de "failles" ou de "portes dérobées" laissées ouvertes par les opérateurs, souvent des adresses (Hosts) ou des services qu'ils autorisent gratuitement (comme l'accès à WhatsApp, Facebook, etc.). En masquant le trafic internet classique pour le faire passer par ces adresses autorisées, les applications VPN de tunneling peuvent contourner les compteurs de données.

Les Bases Indispensables

Qu'est-ce qu'un réseau ?

Imaginez un groupe de personnes qui décident de connecter leurs ordinateurs pour partager des informations. Le résultat est un réseau. Internet est simplement un gigantesque réseau de réseaux, interconnectés par des Fournisseurs d'Accès à Internet (FAI) comme MTN, Orange, etc. Chaque FAI gère son propre trafic et peut décider de filtrer, bloquer ou autoriser certaines connexions, ce qui est à la base même du Free Surf.

Protocoles et Ports

Les protocoles sont les "langues" qu'utilisent les ordinateurs pour communiquer (ex: HTTP, TCP). Les Ports sont les "portes" numérotées par lesquelles ces conversations transitent. Chaque service a son port. Dans le contexte du Free Surf, certains ports sont moins surveillés que d'autres.

Ports Clés et Protocoles courants :

  • 21/20: FTP (File Transfer Protocol). Utilisé pour le transfert de fichiers.
  • 22: SSH (Secure Shell). Essentiel pour les accès à distance sécurisés et le tunneling.
  • 25: SMTP (Simple Mail Transfer Protocol). Le protocole standard pour l'envoi d'e-mails.
  • 53: DNS (Domain Name System). Traduit les noms de domaine en adresses IP. Le "DNS Tunneling" est une technique clé.
  • 80: HTTP (HyperText Transfer Protocol). Le protocole du web non-sécurisé, fondamental.
  • 110: POP3 (Post Office Protocol v3). Un protocole utilisé pour récupérer les e-mails.
  • 143: IMAP (Internet Message Access Protocol). Un autre protocole pour la réception d'e-mails, plus moderne que POP3.
  • 443: HTTPS (HTTP Secure). Le port le plus important pour le tunneling via SSL/TLS, car le trafic est chiffré.
  • 993: IMAPS (IMAP Secure). La version sécurisée d'IMAP.
  • 995: POP3S (POP3 Secure). La version sécurisée de POP3.
  • 1194: OpenVPN. Le port par défaut pour ce protocole VPN très populaire.
  • 8080: Proxy HTTP. Un port alternatif très courant pour les serveurs proxy et le trafic web.
VPN, Host, SNI & Payload

Le Host (ou Hôte) : La porte d'entrée

Un **Host** est simplement une adresse web (ex: `youtube.com`). Dans le Free Surf, un "bon host" est une adresse que l'opérateur laisse accessible même sans forfait data (souvent lié à un service comme WhatsApp, Facebook, ou des services internes à l'opérateur). C'est la faille que nous exploitons.

SNI (Server Name Indication) : Le cas particulier du HTTPS

Le SNI est une extension du protocole HTTPS. Quand vous vous connectez à `https://exemple.com`, votre appareil envoie le nom `exemple.com` **en clair** au début de la connexion, *avant* que le reste du trafic ne soit chiffré. L'opérateur peut lire ce nom. Si le SNI (`exemple.com`) correspond à un service autorisé, il laisse passer la connexion. La technique du **Spoof SNI** consiste donc à mettre un host autorisé dans ce champ SNI pour tromper l'opérateur.

Host vs. SNI : La différence clé

Bien que liés, ils sont utilisés dans des contextes différents. On parle de "Host" dans une requête **HTTP** (port 80), et de "SNI" pour le nom de domaine envoyé dans une requête **HTTPS** (port 443). La plupart des applications de tunneling modernes utilisent le SNI car le trafic HTTPS est la norme.

Le Payload : La Clé qui ouvre la porte

Le Payload est une requête (généralement HTTP) fabriquée à la main. On y insère le Host autorisé pour faire croire au serveur de l'opérateur qu'on accède à un service gratuit. Une fois la connexion acceptée grâce à ce "mensonge", le VPN crée un tunnel pour y faire passer tout notre trafic (vidéos, téléchargements, etc.).

TCP vs UDP : Quelle différence ?

Ce sont deux protocoles de transport majeurs, mais avec des philosophies opposées.

TCP (Transmission Control Protocol)

Imaginez un appel téléphonique : on établit une connexion, on s'assure que l'autre personne a bien reçu chaque phrase (accusé de réception), et on termine l'appel. C'est ce que fait TCP.

  • Fiable : Garantit que toutes les données arrivent dans le bon ordre.
  • Orienté connexion : Établit une session stable avant l'envoi de données.
  • Plus lent : Les vérifications constantes ajoutent un temps de latence.

UDP (User Datagram Protocol)

Imaginez envoyer une carte postale : vous l'envoyez sans savoir si elle arrivera, ni quand. C'est le principe d'UDP.

  • Rapide : Pas de vérification, on envoie les paquets le plus vite possible.
  • Sans connexion : Pas de session pré-établie.
  • Non fiable : Des paquets peuvent se perdre ou arriver dans le désordre. Idéal pour le streaming ou les jeux en ligne où la vitesse prime sur la perfection des données.
  • Pertinent pour le Free Surf : La technique de DroidVPN repose sur l'exploitation de ports UDP ouverts chez certains opérateurs.
Tunneling SSH & WebSocket

Le Tunneling SSH (Secure Shell)

SSH est un protocole ultra-sécurisé utilisé à l'origine pour administrer des serveurs à distance. Il crée un canal de communication entièrement chiffré. En Free Surf, certaines applications VPN (comme HTTP Injector) encapsulent le trafic dans une connexion SSH. L'avantage est une sécurité et une stabilité souvent accrues, rendant le trafic plus difficile à inspecter par l'opérateur.

Les WebSockets

C'est une technologie qui permet une communication bi-directionnelle et en temps réel entre un navigateur et un serveur, sur la même connexion TCP (souvent utilisée pour les chats en direct, les jeux, etc.). Certains Payloads modernes utilisent le protocole WebSocket (`wss://`) car il ressemble à du trafic web normal et peut plus facilement passer à travers les pare-feu des opérateurs.

Tutoriels Détaillés par Application

SocksIP / HA Tunnel Plus (Payload HTTP)

Configuration :

  1. Prérequis : Activer un micro-forfait (ex: MTN WhatsApp 25F) peut être nécessaire pour l'amorçage.
  2. Dans l'app (section "Payload Generator"), entrez un Host fonctionnel de notre section Ressources.
  3. Choisissez la méthode HTTP-BUG ou similaire et cochez les options utiles (Keep-Alive, Online Host, etc).
  4. Cliquez sur "GENERATE".
  5. L'étape la plus importante : modifiez le texte généré pour qu'il commence par HTTP/1.1 200 OK[crlf]. Il faut souvent ajouter le 200 OK manuellement et nettoyer la fin du texte pour qu'il n'y ait pas de code inutile après la requête.
  6. "SAVE" ou "APPLY", choisissez un serveur, puis "START".
AnonyTun / TLS Tunnel (SSL & SNI)

Méthode SNI (la plus simple et efficace)

  1. Dans les paramètres, activez "Stealth Tunnel" ou "Méthode personnalisée".
  2. Protocole de connexion : SSL ou TLS. Port de connexion : 443.
  3. Activez les paramètres SSL avancés ("Advanced SSL Settings" ou "Utiliser l'hôte SNI").
  4. Cochez "Spoof SNI Host". Dans le champ "Spoof Host", mettez un Host/SNI valide (ex: v.whatsapp.com).
  5. Sauvegardez, revenez à l'accueil, et cliquez sur "CONNECT".
DroidVPN (Méthode UDP)

Cette application nécessite un compte gratuit à créer sur le site DroidVPN. Elle est puissante pour exploiter les ports UDP ouverts.

  1. Créez un compte et entrez vos identifiants dans l'application.
  2. Allez dans Settings → UDP Settings.
  3. Configurez les ports selon les failles connues de votre opérateur :
    • Pour Orange (CM): Remote UDP Port: 3128, Local UDP Port: 443.
    • Pour MTN (CM): Remote UDP Port: 3128, Local UDP Port: 80.
  4. Allez dans UDP Connection Mode et choisissez Mode 1.
  5. Configurez les "counts" (TCount / RCount) si nécessaire :
    • Pour Orange (CM): TCount : 2, RCount : 3.
    • Pour MTN (CM): TCount : 0, RCount : 0.
  6. Revenez à l'accueil, choisissez un serveur gratuit ("Free Server") et connectez-vous.
HTTP Injector (SSH / SSL)

Très populaire pour Nexttel/Camtel, il utilise une connexion SSH sécurisée tunnelée via un SNI.

  1. Dans le menu principal, choisissez "SSL/TLS -> SSH" comme type de tunnel.
  2. Dans le champ Server Name Indication (SNI), entrez un Host/SNI fonctionnel (ex: m.facebook.com).
  3. Cliquez sur START. L'application vous demandera de choisir un serveur SSH.
  4. Sélectionnez un pays dans la liste, puis un serveur marqué comme supportant "SSH".
  5. Cliquez une seconde fois sur START pour lancer la connexion.
Stark VPN Reloaded (Payloads TCP/HTTP)

Une application versatile qui permet une configuration facile via des payloads personnalisés.

  1. Ouvrez le menu et allez dans "Custom Settings".
  2. Sélectionnez l'onglet correspondant à votre méthode (TCP, HTTP ou SSL).
  3. Pour MTN, choisissez TCP et entrez un port comme 3128, puis dans CUSTOM PAYLOAD, entrez un payload simple comme :
    HTTP/1.1 200 ok[crlf]Host:google.com[crlf]
  4. Pour Nexttel, choisissez HTTP (port 8080) et un payload avec un User-Agent comme celui dans notre banque de payloads.
  5. Sauvegardez, retournez à l'accueil et appuyez sur le bouton de connexion.

Arsenal Complet & Ressources

L'Arsenal des Applications VPN

Chaque application a ses forces. Votre arsenal devrait en contenir plusieurs :

  • SocksIP / HA Tunnel Plus: Les classiques du Payload HTTP. Simples et efficaces.
  • AnonyTun / TLS Tunnel: Experts des tunnels SSL/SNI. Idéal pour Nexttel et Camtel.
  • DroidVPN: Spécialiste unique du protocole UDP, souvent la clé pour Orange.
  • HTTP Injector: Robuste et sécurisé grâce à son tunnel SSH.
  • Stark VPN Reloaded: Permet d'exporter des configurations protégées.
  • Your-Freedom: Le maître incontesté du Tunnel DNS, discret mais souvent plus lent en version gratuite.
  • Wire Tun / Hero DNSTT: Des VPN "sans config" basés sur le DNS, parfaits pour tester rapidement une connexion.
  • Techoragon VPN / HKH VPN: Alternatives puissantes offrant des options de configuration avancées.

Banque de Payloads Prêts à Copier

Remplacez Host-Ici.com par un host fonctionnel de la liste ci-dessus.

Payload simple (SocksIP/HA Tunnel)

Le plus basique, mais souvent suffisant.

HTTP/1.1 200 ok[crlf]Host: Host-Ici.com[crlf]Connection: Keep-Alive[crlf]Proxy-Connection: Keep-Alive[crlf]

Payload avec User-Agent (pour AnonyTun/Stark)

Le User-Agent aide à simuler un vrai navigateur mobile.

GET http://Host-Ici.com/ HTTP/1.1[crlf]Host: Host-Ici.com[crlf]Connection: keep-alive[crlf]User-Agent: Dalvik/2.1.0 (Linux; Android 10)[crlf]

Payload complexe avec X-Online-Host (très efficace)

Ce payload utilise plusieurs en-têtes pour mieux masquer le trafic.

CONNECT [host_port] [protocol][crlf]Host: Host-Ici.com[crlf]X-Online-Host: Host-Ici.com[crlf]X-Forwarded-Host: Host-Ici.com[crlf]Connection: Keep-Alive[crlf]User-Agent: [ua][crlf]
Astuces & Dépannage

Débit coupé ? Le trick du Mode Avion !

La solution la plus célèbre et efficace quand une config ne se connecte plus ou que le débit chute :

  1. Activez le mode avion. Attendez 5 à 10 secondes.
  2. Désactivez le mode avion.
  3. Dès que le sigle 4G/3G/H+ réapparaît à l'écran, cliquez **immédiatement** sur "START" ou "CONNECT" dans votre application VPN. Cette fraction de seconde est cruciale.

Partager vos configurations

Des applications comme SocksIP ou Stark VPN permettent d'exporter vos configurations. Cherchez l'option "Export Config". Vous pourrez ainsi bloquer le host/payload pour qu'ils ne soient pas visibles, ajouter une date d'expiration, un message personnalisé ou même un mot de passe pour partager vos trouvailles en toute sécurité.
