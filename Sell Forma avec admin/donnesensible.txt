Absolument. C'est une question essentielle. Savoir où modifier les informations clés est fondamental pour gérer votre site au quotidien.

Voici un résumé de toutes les données de configuration "sensibles" ou importantes, où les trouver et ce que vous devez en faire.

Toutes ces informations se trouvent au début de votre fichier js/app.js.

Résumé des Données Sensibles et de Configuration
1. Mot de Passe Administrateur

C'est la donnée la plus critique. Elle protège l'accès à votre tableau de bord.

Où le trouver : Dans js/app.js, à la ligne :

Generated javascript
const ADMIN_PASSWORD = "admin";


Action Requise : Vous devez absolument changer "admin" par un mot de passe complexe que vous seul connaissez. Par exemple : const ADMIN_PASSWORD = "MonMotDePasseSuperSecret2025!";

2. Codes Promotionnels

Ce sont les codes que vos clients peuvent utiliser dans leur panier pour obtenir une réduction.

Où les trouver : Dans js/app.js, c'est l'objet PROMO_CODES :

4. Le "Cœur" de votre boutique : Les Formations

Ce n'est pas une donnée "sensible" en termes de sécurité, mais c'est la plus importante pour votre activité. C'est ici que vous gérez tout votre catalogue de produits.

Où le trouver : Dans js/app.js, c'est le grand objet PRODUCTS tout en haut du fichier.

Avertissement de Sécurité Très Important

Puisque votre site est entièrement statique (HTML, CSS, JS), toutes ces informations, y compris le mot de passe admin et les codes promo, sont visibles dans le code source si un utilisateur sait où chercher.

Pour le mot de passe admin : C'est une sécurité de base qui empêchera 99% des gens d'accéder à votre page admin. C'est suffisant pour commencer.

Pour les codes promo : Un client techniquement averti pourrait trouver la liste de tous vos codes promo en regardant le fichier app.js.

C'est la limite d'un site sans backend (serveur). Pour démarrer, c'est tout à fait acceptable. Mais si votre site grandit et que la sécurité devient une priorité absolue, la prochaine grande étape dans votre parcours de développeur sera d'apprendre un langage backend (comme Node.js ou PHP) pour cacher toute cette logique côté serveur.
